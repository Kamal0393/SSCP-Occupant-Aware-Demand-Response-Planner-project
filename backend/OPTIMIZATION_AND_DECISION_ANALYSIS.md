# Optimization and decision analysis

The CP-SAT adapter keeps the original `DemandResponseSolver.solve(...)` contract and adds `solve_problem(...)` for richer plans. Legacy solvers remain usable through the adapter. The advanced model allocates controllable kW in 0.01 kW units, requires enough reduction to address measured transformer overload, respects the event request as an upper bound, excludes opted-out buildings, and reports infeasible capacity protection explicitly.

Peak reduction and comfort are competing weighted objectives. Running flexible non-HVAC loads can be reduced without a comfort penalty. HVAC-sensitive reductions are limited by the occupant's upper hard comfort bound and scored using `HVAC_SETPOINT_CHANGE_C_PER_KW` (default `0.25` °C/kW). This is a planning proxy and should be calibrated against local equipment and comfort data. Provide `transformer_load_profile_kw` in a planning request for event-window peak and energy analysis; without one, analysis holds measured transformer load constant and accounts for known appliance schedules.

Tariff-aware scheduling applies to flexible, non-running appliances that include `preferred_slot` and `max_shift_slots`. CP-SAT selects a candidate slot within the allowed shift window, uses tariff rates and occupant shift penalty, and prevents a task from being moved into the DR window if it was scheduled outside it. Appliance energy remains conserved; cost differences use the actual before/after slots. `estimated_cost_difference` is optimized cost minus baseline cost, so negative values indicate savings.

Emergency override is explicitly requested with an operator ID and justification, and requires an active DR event, transformer overload, a matching `X-Override-Token`, and occupant `allow_override=true`. A token is accepted only when `OVERRIDE_AUTH_TOKEN` is configured. It waives only that occupant's opt-out; comfort bounds, flexible-load limits, and physical constraints remain in force. Each successful planning request persists the planning result, decisions, deterministic explanations, and planning history. Override history records the operator and justification. The API returns the planning result ID.
